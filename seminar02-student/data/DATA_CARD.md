## Происхождение и ограничения

Все файлы созданы специально для этого курса генератором псевдослучайных чисел. Это **синтетический кейс**, без реальных людей, логов компаний и внешних API. Закономерность времени решения близка к линейной с добавленным шумом; в лабораторном наборе есть категориальные эффекты и искусственные пропуски. Не делать выводов о реальной службе поддержки по этим числам.

Объект — одно независимое учебное обращение. Момент прогноза — регистрация. Target — `resolution_minutes`, время до закрытия в минутах. Наборы первой лекции и лабораторной генерируются независимо; лабораторная не является повторным использованием validation первой демонстрации.

## Словарь полей

| Поле | Единицы / значения | Доступность и действие |
|---|---|---|
| `ticket_id` | Строковый уникальный ID | Только аудит и сопоставление, не вход модели |
| `message_length` | Символы первого сообщения | Известно при регистрации; возможен пропуск |
| `queue_at_open` | Число обращений в очереди | Известно при регистрации |
| `account_age_days` | Дни | Известно при регистрации; возможен пропуск |
| `channel` | chat / email / portal | Канал регистрации; возможен пропуск; в новых примерах также phone |
| `priority` | low / normal / high | Выбранный при регистрации приоритет; не результат последующего анализа |
| `handling_minutes_total` | Минуты | Итог после закрытия, исключается из входов |
| `resolution_minutes` | Минуты | Target; не вход |

В `intro_tickets.csv` нет категориальных полей и `handling_minutes_total`. В `lab_a_new_tickets.csv` нет итоговых полей и target. Пропуск в CSV — пустая ячейка, которую `pandas.read_csv` читает как отсутствующее значение.

## Протокол

Распределение по файлам фиксировано. Train и validation не объединять для нового случайного split. Анализ для выбора преобразований проводится на train. Метки validation доступны для разработки; они не являются финальным независимым тестом. Входные признаки перечислять явно.

Независимость синтетических строк делает обычную случайную проверку приемлемым учебным упрощением. В реальном приложении потребовалось бы отдельно рассмотреть время, повторяющихся пользователей, незакрытые случаи и изменения очередей. Это ограничения примера, не исследованные нами свойства реальных данных.

## Набор для вариантной ЛР1

`tickets_lab1_*` — 2400 новых синтетических обращений, независимо созданных
для четырёх вариантов ЛР1 и второго семинара. Это не реальные дополнительные
наблюдения и не восстановление неизвестного генератора `intro_tickets.csv`.
Исходный файл на 480 строк сохранён побайтно; его SHA-256:
`dc072434983a5e2264bd8d88a0fa3de27f1240e8a0f0c7962f952a12f20e4c18`.

Одна строка по-прежнему означает обращение, а прогноз делается в момент
регистрации. В новый набор добавлены известные в этот момент поля:

| Поле | Смысл и роль |
|---|---|
| `attachments_count` | Число вложений в первом сообщении; числовой вход |
| `active_agents` | Операторы на смене; числовой вход с пропусками |
| `is_weekend` | Признак выходного дня 0/1 |
| `initial_payload_bytes` | Размер первого запроса; числовой вход с пропусками, близкий к длине сообщения |
| `channel` | `web`, `email` или `chat`; категориальный вход |
| `topic` | `access`, `billing`, `integration` или `other`; категориальный вход с пропусками |

`ticket_id` используется только для сопоставления. `resolution_minutes` —
target и отсутствует в student-test. Во втором семинаре из доступной при
регистрации очереди вычисляется `queue_extra`: в отдельных экспериментах это
либо `max(queue_at_open - 18, 0)`, либо квадрат этой величины. Признак не
извлекается из target и заранее в CSV не записан.

Из 1920 размеченных строк 1440 фиксированно отнесены к train и 480 — к
validation. Ещё 480 строк образуют test без ответов. Фолды вариантов 3 и 4
строятся только внутри train; imputer, scaler и encoder заново обучаются на
обучающей части каждого фолда. Validation может использоваться для выбора
настройки, поэтому не заменяет независимый test.

В студенческую поставку разрешены `intro_tickets.csv`,
`tickets_lab1_dev.csv`, `tickets_lab1_test.csv` и `lab1_split.csv`.
Генератор, его параметры и `lab1-test-labels.csv` доступны только
преподавателю. Набор не содержит реальных персональных данных, но его
синтетические зависимости, неодинаковый шум и редкие задержки нельзя
интерпретировать как свойства настоящей службы поддержки.

В отдельный архив семинара 2 входят только `tickets_lab1_dev.csv` и
`lab1_split.csv`: notebook не загружает test и не использует старый
`intro_tickets.csv`.
